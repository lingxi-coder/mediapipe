# Roadmap — YOLO / OBB / Tiling / Backends / Tracking (source of truth)

- **Date:** 2026-06-01
- **Status:** Canonical milestone ordering. This document supersedes the roadmap tables previously embedded in the individual specs; where an older spec uses a legacy `M#` label, map it through the "Prior label" column below.
- **Build model:** Fork / custom build of MediaPipe (not an upstream PR).

This is the single source of truth for **what gets built and in what order**. The earlier per-feature specs accreted out-of-order, dotted/sub-lettered labels (original `M3.5`, `M4.5`, `M6a/M6b`) that no longer reflected sequence. This roadmap replaces that numbering with **build-ordered phases** (the dotted milestones have since been renamed: `M3.5`→`M8`, `M4.5`→`M9`). Backend inference and BoTSORT are intentionally **last**.

## Ordering rationale

- **Phase 1 is done** and stays labelled M1–M4 (shipped, referenced in commits/plans — not renumbered).
- **Phases 2–5 improve the working detector** (public API, caching, video scheduling, GPU zero-copy) before the two heavy end items. Their order is flexible; locally-testable phases (2–4) are placed before the GL-env-blocked Phase 5.
- **Backend inference (Phase 6) and BoTSORT (Phase 8) are last**, per decision. They are independent of each other (BoTSORT does not need new backends), so 6↔8 could swap; BoTSORT is pinned dead-last.
- **Backend-wide zero-copy (Phase 7) sits between them only because it depends on Phase 6** (LiteRT-Next interop needs the pluggable-backend layer). It clusters with the backend work, not with Phase 5.

## Dependency graph (text)

```
Phase 1 (detection core, done)
   ├─► Phase 2 (Tasks API)
   ├─► Phase 3 (caching) ─► Phase 5 (OpenGL zero-copy)   [Phase 5 also needs a GL env]
   ├─► Phase 4 (video scheduler)
   ├─► Phase 6 (backends) ─► Phase 7 (LiteRT-Next zero-copy)
   └─► Phase 8 (BoTSORT)
```

Everything depends only on Phase 1; the sole inter-dependencies among later work are **3→5** (the GL input-tensor pool builds on the cache design) and **6→7** (LiteRT-Next interop needs the backend layer).

## Status legend

- **done** — implemented and tested on `dev`.
- **designed** — has an approved design spec; not implemented.
- **not started** — no spec yet; needs its own brainstorm → spec → plan.

## What's verifiable on the current machine

Group 1 was built CPU-only (`--define MEDIAPIPE_DISABLE_GPU=1`) and is locally testable. Of the remaining phases, **2, 3 (CPU parts), 4, and 8 are locally testable** the same way. **5 (OpenGL) and 7 (LiteRT-Next) need a Linux/Android GL / device environment** this macOS machine lacks; **6** is testable per-platform (ONNX/PyTorch on desktop; TensorRT on NVIDIA; CoreML on Apple).

## Suggested next milestone

Given local testability and value, **Phase 2 (Tasks API exposure)** or **Phase 8 (BoTSORT)** are the most productive to implement next — both are CPU-testable here, unlike Phase 5 (GL env) and the device-specific parts of Phase 6. Phase 6 and BoTSORT remain the final big lifts per this roadmap.
